## Project Overview

**QUAM State Manager** is a desktop + web tool for inspecting and editing quantum machine (QUAM) state files. It reads `state.json` + `wiring.json`, resolves custom JSON pointer references, and provides a CLI, Flask web UI, and pywebview desktop app. It also generates fresh QUAM configurations (Generate Config wizard) and previews `machine.generate_config()` output (Config Viewer).

## Architecture

### Core Pipeline

```
state.json + wiring.json
    → safe_io.read_state_wiring (FILE_SHARE_DELETE + mtime-bracketed pair read)
        → loader.py (QuamStore — owns per-instance pointer cache)
            → pointer_resolver.py (resolves #/, #../, #./ references via store cache)
            → search_index.py (prefix map + trigram index)
            → query.py (flattens nested JSON → qubit/pair dicts)
            → modifier.py (type-coerced edits, undo, rollback)
            → saver.py (atomic writes via safe_io.atomic_write_json, .bak rotation)
            → differ.py (2-way diffs, N-way trends)
            → history.py (Param History: SQLite property index, snapshots)
            → config_view.py (Config Viewer — preview generate_config())
            → config_generator.py (Generate wizard subprocess driver)
```

### QUAM Pointer System

QUAM files avoid value duplication via three pointer types:
- `#/qubits/qA1/f_01` — absolute from root
- `#../x180/length` — relative to parent
- `#./self_ref` — relative to self

`pointer_resolver.py` resolves these **on-read, never in-place**. The cache is **per-`QuamStore`** (each store owns its own dict + lock), so two chips loaded in the same process with same-named qubits never share resolutions. Unresolvable pointers return raw strings + log warnings (real data has dangling pointers). See `docs/32_red_team_phase_2.md` finding 0.1.

### QuamStore (Thread-Safe)

`core/loader.py` holds merged state+wiring dicts, change log, search index, and per-store pointer cache in a single `QuamStore`. All mutations are guarded by `threading.RLock` (Flask workers + pywebview UI thread share state). Loads route through `safe_io.read_state_wiring` so the read never blocks an experiment's atomic save on Windows.

### Working-Copy / Live-File Safety

Experiment programs read and write the same `state.json` + `wiring.json` the app watches; on Windows a plain `open()` for read blocks their atomic `os.replace` save. So the app operates on a **working copy** under `instance/working_state/` (`core/working_copy.py`): the `QuamStore` and `Saver` are built on the copy, background change detection is `os.stat`-only, and the live files are read only on an explicit user **sync** and written only on an explicit **apply to live**. All live-file content I/O goes through `core/safe_io.py` (share-delete reads, `ReplaceFileW` writes, transient retry, mtime-bracketed pair read). LRU eviction in `_activate_quam` keeps the on-disk working folder so a re-load rehydrates unapplied edits via `working_copy.load`. See `docs/28_conflict_safe_io.md`.

**State-roundtrip invariant (docs/65):** content loaded WHOLESALE into the working copy (dataset Load State, State-History stage, Revert last apply) has no change-log entries and a cleared re-apply stash — `/state/sync` must never pull-first over it. A `ctx["staged_base"]` marker overrides the carve-out so staged+edited mixed state still pushes whole. Revert-last-apply's fallback target is content-matched, never the newest snapshot. Pinned by `tests/test_state_roundtrip.py` + `tests/state_sync_selfcheck.cjs`.

**SM never swaps what you are looking at (docs/87).** `reconcile_with_live` no longer auto-pulls on a provably-clean working copy from the user-facing path (`sync_if_clean=False`) — a stale-chip bug's fix used to silently overwrite whatever the user was looking at, which is worse than the staleness it fixed. `auto_adopt` splits by ACTOR, not behavior: the user opening a chip gets `False`; the scheduler's post-node hook and autofit's `reconcile()` get `True` (a robot mid-loop doesn't stop to ask, and autofit's gates need a live anchor). A run started from SM's own Experiment Runner still adopts silently; only writes from OUTSIDE SM raise the drift banner, which now reports "N values differ" from data already read for the verdict (zero added live reads). Pinned by `tests/test_live_replace_routes.py` + `tests/test_sync_robustness.py`.

**A field the entity has not got yet (docs/88).** A cell edit into a leaf whose parent is itself an unresolved pointer used to try to walk into the pointer string. `edit_policy.resolve_missing_leaf_path` only fills in a truly-missing final key (never infers into a list parent); creation stays declared-only via the existing `create` flag, which the grids set from the server's `data-missing` marker. Pinned by `tests/test_missing_leaf_edit.py`.

**The third choice when live drifted (docs/86).** When something outside SM rewrites the live files, the user can now choose a direction instead of only pulling: **↑ Keep mine — overwrite live** sits beside Pull/Sync in both the drift banner and the review modal, gated to skip archives, with a preflight (`GET /state/overwrite-live/preflight`) naming what disappears and one forced confirm (pull and push are NOT symmetric — a pull discards nothing on disk, a push discards live content). A provably-clean working copy still auto-pulls silently (unrelated to this — that's the stale-chip case docs/87 fixed). **One directional-trio vocabulary (docs/97):** every surface now labels the same three actions identically — ↓ Take live / ↑ Keep mine — overwrite live / ⇄ Pull & apply (merge) — instead of six different historical labels. Pinned by `tests/test_overwrite_live.py` + `tests/state_sync_selfcheck.cjs`.

The **load path is content-hash-aware**: each sync point records `synced_live_hash` in the meta sidecar, and `reconcile_with_live` runs on load/select — live replaced + working copy provably clean ⇒ auto-pull; replaced + possibly edited ⇒ keep + `live_diverged` banner (never clobber); unreadable live ⇒ never treated as replaced. Working-copy **GC** deletes only provably-clean copies (transient read failures classify as kept-unverifiable), and its in-use set folds in every LIVE peer window's open chip via `instances.peers()` + `working_copy.key_for`.

### Scanner + LRU Cache + Sidebar Tree v2

`core/scanner.py` discovers experiment folders lazily. `QuamStore` instances are LRU-cached (max 10, ~40MB total) — only loaded when selected in the UI. `node.json` reads also go through `safe_io.read_json`.

**Sidebar tree v2 (r13, docs/68):** `Workspace.tree` stays the flat `{root: [DateGroup]}` data model; `build_nested_tree(root, entries)` derives a VS-Code-style render model per root (real folder levels, date levels descending, leaf entries run-id descending with the 50-cap keeping the newest 50). Staleness = a structure-spine probe: per root, the recorded set of run-parent dirs + ancestors is re-statted as a `{dir → mtime}` map. `rescan_root` scans outside the lock and swaps the tree in one rebind. ### State History

`/state-history` (sidebar; Param History nests under it since r15/docs/69) is a view + restore layer over the same `HistoryManager` snapshot store (no new capture path). **Mode 1 stage** (`/state-history/<ts>/stage`) loads a snapshot into the working copy for review→Apply; **Mode 2 restore-live** (`/state-history/<ts>/restore-live`) replaces the live chip directly. SnapshotMeta carries `label`/`pinned` (prune-exempt). See `docs/41_state_history.md`.

### Typed Editing + State↔Env Validation

Every leaf of state.json (and wiring.json) is dynamically editable, type-safely. **Path grammar**: list/matrix elements use dot-form numeric segments (`confusion_matrix.0.1`), disambiguated structurally from number-keyed dicts by the actual parent container; strict `^\d+$` index gate.

**Type system** (`core/type_policy.py` + `core/state_env_validate.py`): a key's expected type resolves layered — env schema > per-key user assignment (409-confirmed `override_env`) > value inference — through one walk-down resolver and one judge. Invariants: pointers + null always writable; int widens into float; integral floats pass on int-fields verbatim (never rewritten). With no schema/assignment, behavior is byte-identical legacy `_type_coerce`. Assignments persist in `instance/type_assignments/<chip-key>.json`.

**Env schema probe** (`generator/probe_state_schema.py` + `core/state_env_schema.py`): dumps the selected env's dataclass field schemas for the chip's class inventory (version+commit-keyed cache).

**Type visibility (r14, docs/56):** floats display as "real". Stored-as-text numerics are surfaced actively via `diagnostics.numeric_string_leaves` and a delta-gated alarm banner. **One-click repair (docs/77)**: the alarm's "Fix N values…" → `GET /type-fix/plan` (proposal, refuses identity/membership keys, env-schema-`str` fields, leading zeros, separators) → `POST /type-fix/apply` (one Ctrl+Z group; live untouched). **The alert raises itself (docs/78)**: `_arm_type_alarm(ctx, reason)` fires at the three content-entry choke points and `GET /type-alert` consumes the flag one-shot. **Env baselines + user verdicts (docs/79):** `core/state_env_baseline.py` records each probe under `instance/state_schema_baselines/<env_key>.json` keyed by env identity, giving class/field diffs across generations. `core/type_verdicts.py` is the user's correction store (`accept` = stop asking / `override` = a TypeSpec stored verbatim), applied as one manifest overlay at the single `load_policy` choke point. Layering: `user(override_env) → verdict → env → user → inference`. Dormant with no verdict file; an accept-all overlay is a provable no-op (golden-pinned).

**Band-edge headroom is SM's own guideline, not QM's (docs/81):** `BAND_EDGE_MARGIN_HZ` is 5 MHz (only an LO practically on the boundary warns). `extras` is treated as free-form text everywhere (no numeric-string alarm, no type-fix offer, verbatim storage) via `edit_policy.is_free_form_path`.

### Autofit (one-button automatic fitting scheduler)

**Autofit** (`/autofit`; sidebar label "Auto Calibrate" since r15/docs/69) is the closed calibration loop: one button runs a plan of nodes over chosen targets, gates every fit, LLM-audits residual suspects, reverts rejected node writes deterministically, re-measures with adapted parameters, and reports from an append-only ledger. **Doctrine (docs/47, binding): the LLM never emits a number** — its schema is `{verdict, failure_mode, reason}`; corrections are ①deterministic gates ②CAS'd revert via `patches[].old` ③re-run with family-keyed adaptations; calibration numbers always come from the node's own fitter. `core/autofit/`: `families.py` (metric bands + plausibility/jump limits vs the pre-update anchor + feature x-checks, code-curated), `gates.py` (G1 outcome → G4 physical bands → G3 raw-data x-check → G2 metrics/consistency → G5 history), `auditor.py` (per-plan call budget, numeric emissions discarded+flagged), `engine.py` (per-target decisions, hard-criticality halts only that target's chain), `writer.py` (the ONLY write path: build lock → `batch_set` → `saver.save` → `apply_to_live`), `synth.py`/`simbackend.py` (sim chip + corruption modes, indistinguishable to any SM reader), `realbackend.py` (drives the Scheduler chassis). ### Re-generate Config

**Re-generate config** (`/regenerate`) lets a user take a chip they already built, edit its structure in the wizard, rebuild it fresh, and keep every calibrated value, plus emit a single editable Python build recipe. Pipeline (`core/regenerate.py`): `regen_spec.reconstruct_spec` inverts the chip → spec → wizard edits → `config_generator.run_generator` builds fresh structure into a NEW folder → `regen_merge.merge_states` carries calibrated values (tier-1) + grafts user-added subtrees (tier-2) → `regen_script.emit_build_script`. The State Manager process never imports quam/quam_builder.

Entity collections are never resurrected. TWPAs build natively via `Connectivity.add_twpa_lines` (legacy 0.2.0 builders fall back to a wiring-carry graft). Pair ids are reconciled by (control, target) membership at merge AND at build-time populate-seed lookup. A **cross-generation schema gate** refuses to graft an old-only key into a class the fresh build's own dataclass schema doesn't recognize (visibly dropped as `schema_dropped`, never a silent `Quam.load()` crash).

**A pair reference is a POINTER, and it can be TWO hops (docs/118).** A modern quam_builder chip's pair control/target reference is `#/wiring/qubit_pairs/<p>/c/control_qubit` → `#/qubits/qX`, not the one-hop form the old code assumed — every pair was silently dropped from the reconstructed spec, losing 59% of pair calibration on a real 10Q chip while the build still reported SUCCESS. `qubit_ref_name` now walks the chain one hop at a time correctly. Pinned by `tests/test_regen_pair_pointers.py`.

**Adaptive reconstruction + populate-protect (r16, docs/72)**: `reconstruct_spec` unions the declared `ports` inventory into the FEM set, tolerates explicit-null channels, and the merge accepts `protect_paths` so in-wizard Populate edits are never reverted by tier-1. Transparency counters surface in the build-result panel. An exact-spec sidecar at `<out>/.regen/generate_spec.json` is preferred on a later re-generate. See `docs/51_regenerate_config.md`.

### Environment Capability Validation

A build only works if the selected env exposes the exact functions the chip needs, and package versions lie (a lab's `quam_builder 0.2.0` may still have `add_twpa_lines` via a backport). `generator/probe_capabilities.py` runs in-env introspection (`import + hasattr`, stdlib-only at import); `core/capabilities.py` owns `REGISTRY` + `required_capabilities(spec)` + `assess(spec, manifest)` sorted into blocker / degrade / ok buckets. `/generate/build` + `/regenerate/build` enforce server-side. Pulse-class locators are multi-home (quam → quam_builder arch → quam_builder common) since quam 0.6.0/quam_builder 0.4.0 moved several classes out of `quam.components.pulses`. See `docs/52_env_capabilities.md`, `docs/53_qop37_alignment.md`.

### Type Coercion Philosophy

`modifier.py` casts new values to the original field's type but **never validates ranges**. Real QUAM data has coupler amplitudes >1, negative T2, angles outside [-π, π] — trust researcher input.

## Tests

Tests use `tmp_path` synthetic fixtures. Some tests additionally probe real data from `<data-root>\...` and auto-skip when that path is absent. No test config files — pytest uses default discovery. An autouse fixture in `tests/conftest.py` points `QUALIBRATE_CONFIG_FILE` at a nonexistent tmp path so the suite never reads the developer's real `~/.qualibrate` (docs/63). The qualibrate/project-scope test files also run green on native Windows — their fixtures interpolate TOML paths `as_posix()` (raw backslashes are escapes inside TOML basic strings and silently void the whole config). See the Commands section above for the current `cqt`-env baseline — re-derive it in whatever env you use rather than trusting a number from a different or since-removed env.

## Dependencies

Core: Flask, Jinja2, Typer, Rich. Desktop: pywebview. Data: h5py (HDF5 reading), numpy + scipy (Pulses-page waveform synthesis — scipy gives bit-exact window/filter parity with qualang_tools). Frontend: HTMX, Pico CSS, Split.js, Plotly.js — all bundled in `web/static/` (no CDN). The Generate-Config wizard shells out to a user-selected conda env that has the heavy QM stack (`qualang_tools`, `quam_builder`, `quam`, `qm`) installed; the State Manager process itself never imports them.

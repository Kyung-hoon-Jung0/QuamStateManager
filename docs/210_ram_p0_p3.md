# docs/210 — Datasets > Trends served from RAM, not from re-rendered DOM

2026-09-25/26, branch `feat/ram-p0-p3` (7 commits), merged `1184bc5`. Design:
`D:\work\sm_qa_rigs\_findings\ram_design.md`.

## 1. What was measured

`16_iq_blobs` (962 runs) opened cold on the 4,121-run KH archive:

| | before | after |
|---|---|---|
| first chart | 1,969 ms | 104 ms |
| client long tasks | 2.5 s | 58 ms |
| DOM nodes | 31,504 | 2,766 |
| fragment payload | 2.44 MB | 123 KB gz |

## 2. Cause

`Datasets > Trends` shipped the whole answer as DOM: one `<img>` per run per
figure key (3,848 on `16_iq_blobs`), a Parameter Differences table with one
column per run (962 columns, 6,741 cells) and 962 categorical x labels —
31,504 nodes that every Plotly layout pass then reflowed. The server side
was cheap; the browser froze for seconds turning it into pixels.

## 3. P0-lite — the foundation (`1fd941b`)

`ram_design.md` §1 ("validate on read"): `core/ramcache.KeyedMemo`,
slot → `(token, value)`. A lookup compares the stored token against the
caller's freshly computed one — a mismatch is a miss, never a stale serve.
Single-flight per `(slot, token)`; a waiter past `wait_s` gets `Warming`,
not an older value. Byte-accounted (per-memo `max_bytes`/`max_entries`, one
LRU across all memos under `SM_RAM_BUDGET_MB`, default 384).
`DatasetStore` gained `instance_seq` (never reused), `generation` /
`exp_gen[exp]` bumped at every runs-list mutation, `meta_generation` at
every tag/note/bookmark write, and a bounded run event log so a reader can
tell "only newer runs arrived" (cheap append) from anything else (rebuild).
`GET /debug/ram` exposes budget/entries/hit-miss/compute-ms per memo.
Pins: `tests/test_ramcache.py` (14), `tests/test_dataset_generation.py`
(25); mutation sweep over 19 bump sites + 11 `KeyedMemo` behaviours.

## 4. P3 — Trends served from the RAM index (`7a8e239`)

`core/trend_index.ExperimentTrend`, one per `(DatasetStore, experiment)`:
complete runs in run-id order with instants, qubit sets, figure names,
parameters, one value array per `(qubit, metric)`. Validated on read against
`store.exp_gen[exp]`; a new newest run is an append (copy-on-write — a
reader holding the old object never sees a half-appended one), anything
else rebuilds that experiment only.

- `GET /trends/data` is now a light shell — no `<img>`, no table, no data.
- `GET /trends/series` — gzipped JSON, ETag = the index version (304 on
  repeat), `202 {"warming": true}` for a concurrent compute.
- `GET /trends/param-diff` — only differing rows over the newest 20 runs
  with exact counts, and a "show all" option.
- Client (`window.DatasetTrends`): x = the run's real instant; lines drawn
  only above 200 points; the Figure timeline built only when opened; one
  chart per task; Plotly preloaded while idle.
- M4 downsampling deliberately NOT implemented — at the measured scales
  (≤~1,000 runs/experiment) no series exceeds 4×W points for a ~1,000 px
  chart.

Pins: `tests/test_trend_index.py` (staleness event by event, a 200-step
random sequence under `SM_RAM_VERIFY`, a 12-component key sweep),
`tests/test_trends_routes.py`, `tests/trends_view_selfcheck.cjs`; 50/50
mutations red.

## 5. Found by the real-Chrome verification of P3

- `3d5d80a` — the `/trends/series` ETag was a digest of process-local
  counters only, so a browser holding an ETag across an SM restart could be
  answered a stale 304 whose counters happened to line up (reproduced: a
  fresh tab's first open already came back 304). The version now carries a
  per-process boot token.
- `687b014` — a concurrent Parameter Differences request that timed out its
  single-flight wait answered a dead-end "pick again in a moment". It now
  answers an explicit placeholder that re-fetches the SAME request itself.
- `5200b96` — the first `/trends/series` after a run landed still cost
  0.7–2 s in the browser because the request paid the store's incremental
  rescan inline. `core/run_ingest.RunIngest` (one coalescing daemon thread)
  now does that rescan + `trend_index.refresh_store` off the request path,
  on the run-watch tick; correctness never rides on the tick running in
  time, since every memo is still validated on read. Pins:
  `tests/test_run_ingest.py`, 10/10 mutations.
- `b16270f` — a run still mid-write (its later files land inside the run
  folder, which moves no date-dir mtime) closed `rescan_if_stale`'s gate
  and stayed "incomplete" — excluded from Trends — until an unrelated run
  landed elsewhere. The gate now stays open while `_incomplete_paths` is
  non-empty, bounded by `_INCOMPLETE_MAX_TRIES`.
- `7f84abc` — a handful of failed-fit values (e.g. 68 ms / 23 ms beside 49
  values at 3–30 µs) forced Plotly's autorange to flatten a whole Metric
  Trends chart. Values beyond Tukey's far-out fences that stretch the axis
  >20× the rest's span now draw as edge triangles instead, with their real
  value on hover; the data trace is untouched. `[derived]` heuristic,
  thresholds set against the archive's 508 series (35 rescaled, 60 of
  28,666 points off-scale).

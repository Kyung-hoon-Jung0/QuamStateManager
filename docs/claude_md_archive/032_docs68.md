**Sidebar tree v2 (r13, docs/68):** `Workspace.tree` stays the flat `{root: [DateGroup]}` data model; `build_nested_tree(root, entries)` derives a VS-Code-style render model per root (real folder levels, date levels descending, leaf entries run-id descending with the 50-cap keeping the newest 50). Staleness = a structure-spine probe: per root, the recorded set of run-parent dirs + ancestors is re-statted as a `{dir → mtime}` map. `rescan_root` scans outside the lock and swaps the tree in one rebind. The active run's ancestor `<details>` get `.tree-branch-active` so a collapsed tree still shows where the open experiment lives.

**The config picker gets the explorer, files become pickable, the dialog learns the keyboard (docs/149, 2026-09-01).** The landing's QUAlibrate config picker gains a Browse… button opening the shared folder browser in `kind="config"` mode: dot-dirs SHOWN (the default filter hid `.qualibrate`), the folder's `*.toml` files render as selectable rows (a file is a pick, not a place — click fills the path, Select/Enter confirms; `/browse` with an existing FILE path lists its parent WITHOUT the lying "was not found" note), `config_dirs`/`has_config` highlight and badge. Keyboard navigation ships for EVERY dialog mode (arrows + Enter/Right descend, Left/Backspace up, Home/End, dot-insensitive type-ahead — "qual" finds `.qualibrate`), and the Check button stops rendering full-width (Pico's `[type=submit]{width:100%}` — `.locate-form .btn-sm` pins `width:auto`). **Load-order lesson**: the keydown listener was first registered in a load-time IIFE — app.js evaluates in `<head>` before the `<dialog>` exists, so it silently bound nothing; real Chrome caught what jsdom hid, because the harness builds the dialog before evaluating app.js. Binding is lazy now (`_kbBind()` from `openFolderBrowser`) and the harness's late-dialog world (`makeWorld({lateDialog:true})`, G14) reproduces the real order. Pinned by `TestConfigKind` (test_browse_route.py) + G12/G13/G14 (folder_browser_selfcheck.cjs).

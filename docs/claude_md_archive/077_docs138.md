**A 2Q RB number is per-Clifford or per-gate (docs/138, 2026-08-24).** Customer report: the topology headline said the q19-20 CZ was **97.1%** while the per-pulse sections on the SAME page said 99.09% and 99.34%. `StandardRB` is **1−EPC (per Clifford)**, `InterleavedRB` is **1−EPG (per gate)** — established three ways: arithmetically (`(d-1)/d·(1-α)` and `(d-1)/d·(1-α_int/α_ref)` reproduce both to 1e-12, d=4), from the lab's node docstrings ("fitted average **Clifford** fidelity" vs "fitted **CZ-gate** fidelity"), and from their `two_qubit_rb/fidelity.py:87` (`epg = epc/average_gates_per_clifford`; the node computes `average_gate_fidelity` and then stores only the Clifford one). On this chip `average_gates_per_clifford = 5.371` — a Clifford is over FIVE 2Q gates, so the two are nowhere near interchangeable. Three defects, one cause (`_extract_pair_gate_fidelities` emitted every numeric key as an undifferentiated fidelity row): ① `EDGE_METRICS` order sets the default, `cz_fidelity` came only from `Bell_State` so on an RB chip it was filtered out and the CLIFFORD metric became the default; ② `*_alpha` — the RB decay base — rendered as `95.62%` under a heading reading "Gate fidelity"; ③ the edge was grey on a pair characterised by interleaved RB, the better measurement. Fixed: `query._RB_LEVEL` stamps each row `gate`/`clifford`/`state`/`decay`; the edge takes `InterleavedRB` when there is no Bell_State (`fidelity_source="interleaved_rb"`, `best_gate` = the winning pulse) while **`StandardRB` is deliberately NOT a fallback** (a per-Clifford number would understate every gate); the gate metric is offered BEFORE the Clifford one; patches read `2Q gate (IRB)` / `2Q Clifford (SRB)` where both read `2Q RB`; α gets its own "RB fit (decay α)" section as bare numbers; and `2Q Bell` → `2Q gate fidelity` (that tile reads `cz_fidelity`, whose source is Bell / IRB / CR channel — already wrong on a CR chip). **The stored metric choice is versioned** (`quam_topo_hero_metric_v2`, the docs/85 `_cols_v2` precedent): nobody picked the Clifford number on purpose, they got it as a default under a label that did not say what it was. **Clifford→gate IS derived now (user-approved).** `core/rb_gate_fidelity.py` follows `StandardRB_load_id` to that run's `data.json` and READS the `average_gate_fidelity` the node already computed — never recomputes it. Wired into both topology entry points via `routes._topology_with_derived_rb` (deep-copies first: `get_topology`'s result is CACHED) with `_rb_run_folder` doing the bare-run-id lookup WITHOUT `/dataset/by-run`'s rescan-and-retry, because this runs while rendering. Shown BESIDE the Clifford value (`→ 99.44% per gate ÷5.37`) plus a `2Q gate (SRB÷)` hero patch, never instead of it. Degrades to a blank on a missing/older/unreadable run — measured on the demo chip: cz_unipolar 0.967162→0.993886, cz_gaussian_bipolar 0.970461→0.994499, and cz_flattop BLANK because run #2655 is not on disk. The SRB-derived and IRB numbers are independent estimates and agree to 0.4-0.8%. (Correction worth recording: I first reported that divisor as absent everywhere — I had checked one unrelated run and generalised. It is in `#2271/data.json`, and it is 5.371, not the 1.5 one might guess.)

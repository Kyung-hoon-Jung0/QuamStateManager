**Perf diagnosis + the Param History fix (docs/139, 2026-08-25).** Two measured causes, both fixed. ① Live State Edit's constant 4–5s click: server is 0.5–1s; **the htmx SWAP of the ~MB 452-col grid fragment is 2.4s** + 0.65s settle, and `/bulk` is not in PaneState's KEEP tier at all (`KEEP=['/explorer']`); `/explorer` keep-alive WORKS (`paneRestored` verified; an "empty stash" reading was a stale-alias artifact — `_historyReset` reassigns `stash={}` so the exported `_stash` points at a dead object) but docs/110's "never cancel the request" doctrine means a restore still pays fetch+fresh-insert and discards it. NOT a regression: the always-cold render grew with the grid (docs/94 cap, docs/126 + docs/136 columns). **Fix 1 shipped (2026-08-26)**: `/bulk` joined KEEP and an `htmx:beforeRequest` interceptor cancels the GET when a FRESH parked copy exists (same seq+chip gate as `_tryRestore`), restoring synchronously and pushing the URL itself — measured 4–5 s → **1.0 s** on a RETURN (a cold first visit is 6.9 s and unchanged by design — nothing is parked yet) with zero requests sent; the cancel also carries `stopImmediatePropagation` because three downstream listeners counted the cancelled event as a live xhr and never cleared — NavProgress's bar ticked forever (customer-reported at 154 s) while polling `/api/progress` every 350 ms; `_verifyRestore` stays as the server-truth safety net. Back needed two live-found follow-ons: a `data-pane-route` stamp + mismatch-refetch in `_historyReset` (htmx's `currentPathForHistory` doesn't move on a foreign pushState, so it POISONED its own history cache — content saved under the wrong URL; the repair purges `htmx-history-cache`), and a 1 s dedupe token for the popstate/historyRestore double-fire. Honest residual: Back off the bulk grid freezes ~2.7 s in htmx's own history serialization (pre-existing), and Back after a skip converges ~1–2 s late. Pinned by `pane_state_selfcheck.cjs` (28 asserts, 7/7 mutations). ② Param History 18–22s cold / 0.13s warm: cProfile — `scan_workspace_alignment` is 97%, reading **every run's state.json+wiring.json (2,653 runs × 2 files = 15.1s of read_json)** to fingerprint them, with the cache in-memory only, so every SM restart re-paid it. **Fix 2 shipped (2026-08-25)**: the fingerprint cache persists to `instance/history/_fingerprints.json` (same `(state mtime, wiring mtime)` key — run archives are immutable, so entries never invalidate), loaded lazily with memory-beats-disk `setdefault`, flushed once per alignment scan behind a dirty counter; a corrupt sidecar or bad entry degrades to recompute, never a crash. Measured: restart-case first hit **18–22s → 0.5s** (cold compute 10.6s, 4.6MB sidecar). Follow-on: `_workspace_token` gained an optional `own_root` exclusion (the flush bumped `instance/history`'s mtime, and with the instance dir nested in a workspace root the token sweep read SM's own bookkeeping as "workspace changed", invalidating the scan's own cache) — kept a STATICMETHOD because `routes._dataset_candidate_folders` calls it unbound.

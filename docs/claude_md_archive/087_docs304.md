**Pre-deployment verification (v1.3.0, docs/304).** `tests/state_model/` is a seeded model-based harness (oracle + ops through the real app + invariants I1-I12, each with a planted fault) and `tests/state_model/repros/` holds one pin per finding; `tools/trends_oracle/` recomputes Trends from raw run folders and live backups; `tests/test_pulses_lab_truth_contract.py` checks pulses against the lab's own class code. Contracts it fixed: every staging door is in the mutator lock set (an inventory pin enumerates them); an Apply/Save refuses when another process changed the shared working copy (content digest); no door writes an empty chip state; a torn/unreadable read never decides chip identity or ledger routing; Trends composites (derived fidelities, pointer-followed values) are judged as one holder over the saved input tuple, and a restoring row leaves a series only when it equals the value in force (verdict codes unchanged); pulse references resolve as quam does (missing key -> class default, another pulse's inferred length computed, lab-only properties asked of the lab worker, else an honest reason -- `core/pulse_refs.py`); history migrations never delete history data.

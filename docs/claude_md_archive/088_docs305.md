**Generic Interactive and map tools (v1.4.0, docs/305).** Interactive defaults to the experiment's own plotting code, with current code, a labelled run-time git heuristic, then saved figures/raw data as the reproduction ladder. Analysis fingerprints and source stats invalidate the bounded RAM/disk cache. Plot and waveform interpreters each keep their own lab-worker slot under ONE machine lock (lab code never runs twice at once; the same kind retires, the other kind survives, an env change retires both), with idle, time and RSS limits. A cache miss answers the menu at once with the saved/recipe figures and runs the replay as a background job whose honest phases (`@@SM-IPLOT-PROG@@`: importing lab code / loading run state / drawing figure i of N) the client polls via `/dataset/<uid>/interactive/status` -- never a %; an import failure is cached against its watch set (2026-11-02, tests/test_interactive_job.py). Learned clicks prove marker arithmetic against applied patches or clearly labelled proposals; missing, ambiguous or default-derived proof stays display-only. Smooth / Contour / Fit use full server arrays, measured strength caps and a saved-value comparison; Apply replays the server's numbers. Optional bounded provenance follows the existing edit door through Review, restart, undo/redo and the ledger. The running QUAlibrate config/data hints use cached background discovery and only adopt settings inside SM. Large runs fall back to saved/raw views; the measured coverage and remaining limits are in docs/305.

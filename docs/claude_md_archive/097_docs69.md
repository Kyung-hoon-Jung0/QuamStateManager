`/state-history` (sidebar; Param History nests under it since r15/docs/69) is a view + restore layer over the same `HistoryManager` snapshot store (no new capture path). **Mode 1 stage** (`/state-history/<ts>/stage`) loads a snapshot into the working copy for review→Apply; **Mode 2 restore-live** (`/state-history/<ts>/restore-live`) replaces the live chip directly. Both write through the single build lock and rebuild every derived cache via `_rebuild_after_working_copy_replaced(ctx)`. restore-live's safety gates are independent: origin≠live (archive→409), unsaved edits, wiring-topology mismatch — one token never collapses two gates, and the current live is snapshotted first so a restore is reversible. SnapshotMeta carries `label`/`pinned` (prune-exempt). See `docs/41_state_history.md`.

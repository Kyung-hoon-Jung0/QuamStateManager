**Runner + AI calibration agent (docs/78 — read §17 before trusting any earlier section).** Turns Autofit into a one-button bring-up loop over the 9 families of the x180 chain: press → experiments run → fits gated → state updated → done when gates PASS and a vision judge accepts the signature. **Shipped: P0–P8 + §17 B3. Open: P3c/P3d (needs an API key), P9 (needs hardware).** Doctrine amendment (D-1): a number the AI emits never reaches state.json before passing a tier-A/tier-B verifier. A verification context is the triple (env × analysis-tree revision × run generation) — `envmatrix.py` classifies it, `sourceroot.py` materializes a pinned git revision read-only. `families.py` bands are corpus-derived, never invented (replay real runs, split by the node's own verdict). Update targets are run-derived (flux-point routing, `{operation}` filled and followed through the alias pointer). The vision judge's family knowledge is versioned data (`judge_pack.py`) with shape/geometry-only exemplars enforced at load. `auditor.py` carries four number-free asks: `judge`/`signature`/`compare`/`triage`, all with safe unavailable-defaults. A target is done only when gates pass AND the judge signs off, or — with no judge configured — on gates alone, stamped `vision=unavailable` so no report implies an unperformed check. Also shipped: `action_space.py` (bounded proposals, `load_data_id` blocked on the agent path), `stoploss.py` (three tiers), `consistency.py` (cross-run review), `notify.py`, `replay_score.py` (offline scoring by fewer-runs-to-conclusion). Every verdict carries the context it's valid inside (`verification.py`) — values from different contexts are never compared. `power_rabi`'s `verify_wide` is a mode switch (two distinct experiment shapes), not a scaled span.

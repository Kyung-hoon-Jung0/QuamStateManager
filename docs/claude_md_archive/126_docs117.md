**Auto-apply — the covenant amended (docs/117; amended again by docs/160 above, which adds the undo/redo of an applied change).** A direct live write happens on an explicit Apply press **OR** inside a user-enabled auto-apply session (default OFF, always visible, auto-disarmed on conflict) — the floor (one explicit act) didn't move, its scope did (the act now authorizes a session). `/state/apply-to-live` stays the ONE live writer; the session is a `MutationObserver` on the tray (`web/static/auto-apply.js`) that flushes immediately and coalesces anything arriving mid-flight into one more flush, sharing `window._applyInFlight` with manual Apply. The applied log is the undo journal labelled (`meta.src == "auto"`), whose ✕ is compare-and-swap so a later write to the same path can't be silently clobbered. Cannot arm on archive/read-only/already-diverged chips. Pinned by `tests/test_auto_apply.py` + `tests/auto_apply_selfcheck.cjs`.

**Datasets > Trends served from RAM, not re-rendered DOM (docs/210, 2026-09-25/26).** Design `ram_design.md`. P0-lite: `core/ramcache.KeyedMemo` (validate-on-read, single-flight, byte-budgeted) + `DatasetStore` generation counters, the foundation everything else validates against. P3: `core/trend_index.ExperimentTrend` per `(store, experiment)`, copy-on-write on a new-run append, full rebuild otherwise; `/trends/data` is now a light shell, `/trends/series` ships gzipped JSON with an ETag. Measured on `16_iq_blobs` (962 runs): first chart **1,969 ms → 104 ms**, long tasks **2.5 s → 58 ms**, DOM **31,504 → 2,766 nodes**, payload **2.44 MB → 123 KB gz**. The real-Chrome reverify of P3 found four more: a cross-process-stale ETag (a boot token now guards it), a dead-end "pick again" placeholder for a busy Parameter-Differences compute, run ingestion moved off the request path onto the run-watch tick (`core/run_ingest.RunIngest`), a mid-write run closing the rescan gate early, and a few failed-fit outliers flattening a whole Metric Trends chart (now drawn as edge triangles). **P1, P2 and P4–P10 of the design are not done yet.** Pinned by `tests/test_ramcache.py` (14), `tests/test_dataset_generation.py` (25), `tests/test_trend_index.py`, `tests/test_trends_routes.py`, `tests/test_run_ingest.py`, `tests/trends_view_selfcheck.cjs`.

**Re-opening a chip is a byte digest, not a re-parse (docs/216, 2026-09-27).** A pristine chip leaving the context LRU parks its store, engine and pulse index in `chip_park` keyed on the working files' byte digest, taken back only if a settled re-read gives the same digest and the store is still pristine; the search index is lazy (installed only if `mutation_seq` did not move), and one prewarm worker — waiting for a quiet server, yielding to foreground requests — warms the chip's pointer cache, `lint_state` and env analysis into the same seq-keyed memos the request path reads. Independent verifier on big30x: warm re-open 7144 → 130 ms, evicted re-open 16900 → 502 ms, staleness journeys J0-J5 equal to a cold reload. Pinned by `tests/test_chip_park.py`, `tests/test_chip_prewarm_diag.py`, `tests/test_prewarm_gate.py`, `tests/test_search_index_build_parity.py`, `tests/test_coldopen_io.py`.

**Clear the agent conversation (docs/297).** The Agent panel's strip offers **Clear…** (a sheet: Archive and clear / Delete and clear / Cancel). The index + archive are written FIRST (`instance/agent_conversations/<chip NAME>/`, the identity the feed filters by); only then does the in-app session end and its `session_id` leave the session record (a cleared id is never resumed). `chat_cards`/`/chat/events` show chat events with `n > since_n`; numbering and writing an event are one step under `_REC_LOCK`, which the clear also takes to read the counter; `chat_n.txt` is re-read on every number (another SM process). A window that sees `since_n` change drops the conversation and plan/run cards -- never an approval card or a card being typed in. Archive = a self-contained copy (every day file since the previous clear, not the 800-line ring); Delete keeps none in SM. Never touched: live plans/runs, drafts, approvals, the Calibration log, the agent event log, the CLI's own session files. Refused (409, in the sheet) while anything of the conversation works, or when the sheet's `since_n` is stale; an unreadable index is never rewritten. Pinned by `tests/test_agent_clear.py` + `tests/agent_clear_selfcheck.cjs`.

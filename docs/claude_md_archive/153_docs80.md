**Multiple windows on one machine (docs/80).** `core/instances.py` registers every live SM process (`instance/instances/<pid>.json`, one file per process, liveness by PID probe) — bookkeeping only, never blocks. **Run ownership**: `run.owner_pid`/`owner_port` are claimed at `start` and released at every terminal transition; a live foreign owner makes `start` raise `ForeignRunnerError` → 409 (the one hard refusal — two workers on one OPX is never safe); no/dead owner is byte-identical to pre-fix behavior (crash recovery). Only the SAME state path open in two live windows raises a warning banner. **Two chips at once**: runner state is keyed by chip under `instance/scheduler/<chip>-<fs_key hash>/`; machine-wide settings (env, calibrations folder, timeout) stay shared at `scheduler/_shared.json`; the UI heartbeat is deliberately NOT chip-scoped (switching chips must not pause a run you navigated away from). Pinned by `tests/test_multi_instance.py` (ownership matrix vs a real spawned process) + `tests/test_scheduler_scope.py`.

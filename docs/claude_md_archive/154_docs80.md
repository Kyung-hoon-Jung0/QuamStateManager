**Polling under a concurrent writer (docs/80).** Scan reads use `safe_io.scan_json` (one attempt, no retry ladder — a mid-write run just isn't finished yet, retrying it is pure latency). A present-but-unreadable file marks the run `incomplete`, forcing re-parse without defeating the date-dir short-circuit for its siblings. `/datasets/changes-since` isolates each folder (one raiser can't 500 the whole poll), holds a failed folder's cursor, has a wall-clock budget reported as `partial`/`skipped`, and can only return 200; the client aborts at 10s and backs off on failure. **The delta cursor delivers each change exactly once (docs/202 §18):** every stamp a scan writes goes through `DatasetStore._stamp()` (strictly after any cursor already issued), and `changes_since` takes its cursor via `_issue_cursor()` under `_scan_lock` together with the snapshot. Two independent `time.time()` reads used to tie inside one coarse Windows tick and drop the new run for good, and a cursor read after the snapshot lost runs a concurrent scan stamped in between. That was the long-standing ~30% `TestPollEndpointUnderWriter` flake. Pinned by `tests/test_poll_stability.py` (real folders, real truncated JSON, a live background writer, `TestEveryChangeIsDeliveredExactlyOnce`) + `tests/dataset_poll_selfcheck.cjs`.

**The rack was cropped, not truncated (docs/135, 2026-08-23).** Same session, three reports. ① **The wiring diagram was clipping FEMs on every surface.** `renderInstrumentWiring` set `width=<natural>` + inline `max-width:100%` with **no viewBox**: the element's box shrank while the drawing kept its coordinates, so everything past the pane was painted outside the visible box — and because the element then *fitted*, `overflow-x:auto` never saw an overflow to scroll. One chip read as "3 MW + 4 LF" on `/instrument` (1194px pane) and "3 MW + 2 LF, cut off" in the wizard (862px) when it really has 3 MW + 5 LF; the data was right on both (`reconstruct_spec` → 8 FEMs / 79 lines, and `buildInstrumentData` already adds every step-3 FEM). Now every rack carries a viewBox + its natural size, and `_applyInstrumentFit` picks one of two honest presentations: **Fit** (viewBox scales the whole rack in) or **1:1** (intrinsic px, the host genuinely scrolls) — default Fit while legible (`_INSTR_FIT_FLOOR = 0.55`), 1:1 below, the viewer's `localStorage` choice always winning, a sticky `left:0` bar only when the rack overflows, and a container `ResizeObserver` (docs/122's lesson) re-deciding on pane changes. Inside the renderer, so it reaches page + wizard + compare + floating panel at once. ② **6.1 s → 1.8 s to the zero-click diagram**: `conda env list --json` measured **4.0 s** and sat in front of the whole chain, so `_conda_env_paths` memoizes it on an mtime fingerprint (`~/.conda/environments.txt` + each env's parent dir — what creating/removing an env touches; failures never cached; `?refresh=1` escapes), warmed in a daemon thread at `create_app` (skipped under `testing` or `SM_DISABLE_ENV_WARMUP=1`, which `tests/conftest.py` sets). And the wait now SAYS so — `busyHtml` + a pure-CSS `.sm-dots` ellipsis, each phase named (`Finding a Python environment…` → `Checking wiring…`) in the diagram host **and at the button**. ③ The QDAC driver was never missing (`instr.qdac` probes available in `cqt`; a stale `PYTHONPATH` was shadowing `quam_config` with another customer's copy) — but the reconstruct renderer prefixed EVERY note with ⚠ in warn colour, so `regen_spec`'s carry note read as a problem; `ReconstructedSpec` now splits `notes` (could bite, ⚠) from `info_notes` (statements of fact, muted ℹ), the note states the fact and points at the capability check instead of asserting a requirement it cannot know, and `_nat_key` orders the qubit list q2-before-q11. ⑤ **The wizard's diagram was missing every digital trigger port** — `/instrument` drew the DIG column (docs/126 #22), the "Modify wiring…" step-5 diagram drew none. Two stacked causes: `run_allocate` never ran `_allocate_qdac_triggers` (the isolated `"qt"` pass — docs/119 — that only **build** mode called), and `buildInstrumentData` had no digital branch at all. Both fixed; trigger ports render but are deliberately **not draggable** (they come from `spec.qdac`, not `spec.lines`). **That then exposed a re-cabling bug**: the real chip drives one OPX digital output per QDAC ext trigger input, SHARED — 11 qubits on 4 ports, port N ↔ extN — while `_allocate_qdac_triggers` gives every biased qubit its own dedicated port (a docs/119 decision, fine for a fresh build, silent re-cabling on a re-generate). `reconstruct_spec` now carries each qubit's existing pin as `spec.qdac.qubits[q].trigger_pin` and the allocator honors pins verbatim (sharing round-trips for free; a pin on an undeclared FEM is dropped with a note; a malformed one warns and falls back; an all-pinned chip returns before `qualang_tools` is imported). **Proven by a real rebuild: trigger wiring byte-identical to the source chip.** ④ **The step-5 drag ghost carries the port itself**: `portGlyph` CLONES the dragged node out of the rack into a small `<svg>` (viewBox = its own `getBBox` + stroke pad, size from `getBoundingClientRect` so it matches the rack at either presentation, floored at 24px) — never re-drawn, because role colour/radius/label truncation/chord-fitted font all live in `app.js`'s `_appendPortCircle`. A feedline **grip** carries the whole `.iw-port` cell, not the grey bar; the lifted node dims (`.iw-port-lifted`, cleared in `removeDragGhost` since a cancelled drag never re-renders); a stale validity ring is stripped (it is about the target); the text label stays because a fit-scaled circle's own label is unreadable; no `getBBox` ⇒ the old dot, never a throw.
